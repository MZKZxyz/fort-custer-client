The author inspected native light/dark alpha backgrounds, dusk grayscale and representative wall overlap captures. The wall wells remain inside the blocked footprint. Shared footings meet and the slight paired upright/slat joints do not become corridor-width openings. No unpainted gap or opaque matte was observed in these captures. The explorer can lose part of its boots to a foreground wall, as expected from the selected projection; its body and independent direction cue remain apparent. X keeps its cylinder/lever/hose silhouette, F its pointed tongues, and E its roof/entrance plus explicit E cue. This is a finite observation, not proof of arbitrary-grid physical occlusion or universal human recognition.

Ground is continuous beneath bodies and separate shadow passes. The kit is intentionally small: repeating one ground and one wall is visible. The fixed dusk softboxes do not recreate the original scene's local lantern pools. Shadow overlap can darken corners and the catcher noise-floor treatment slightly shortens very soft tails; neither encodes traversability. These tradeoffs need Art/independent QA acceptance before expansion.

## Objective evidence

[report.json](report.json) is the machine-readable source for screen geometry, logical traces, depth permutations, controls and serial 30-second optimized benchmarks. [production-isolation.json](production-isolation.json) pins the base and protected source hashes. [Asset manifest](../assets/manifest.json) contains exact bounds, pixel anchors, source/PNG hashes and budgets.

Observed on **AMD EPYC 9V45, Linux 6.18.55, Chromium 154.0.8037.57, Node 24.19.0**, using the optimized standalone bundle:

| Check | Measured result |
| --- | --- |
| Largest measured ground-anchor error, 8 screen/DPR combinations | **0.0147 CSS px** (≤0.5 target) |
| Projected pitches at 36 / 44.25 / 48px cells | **30.5297 / 37.5261 / 40.7063 CSS px** |
| 13×17 projected / square frame p95 | **16.7 / 16.7ms**, effectively 0% regression |
| 21×21 projected / square frame p95 | **16.7 / 16.7ms**, 0% regression |
| 13×17 input-to-updated-frame p95, projected / square | **16.6 / 16.6ms** |
| 21×21 input-to-updated-frame p95, projected / square | **16.6 / 16.5ms** |
| Observed long tasks in four serial 30-second runs | **0** |
| Frame/input samples per run | **1,802 frames / 146–147 successful inputs** |

Anchor measurements include the browser's actual image rectangles and CSS subpixel quantization. The pitch formula is checked for every ground row, while the measured anchor-error bound also bounds adjacent-row spacing error to <0.03 CSS px. Raw numbers retain floating point precision in the report; the tiny negative 13×17 regression is numerical noise, not a performance improvement claim. JS heap ended lower in both 13×17 runs and higher in both 21×21 runs; the report retains all four snapshots. No memory-leak conclusion follows from these short runs.

Benchmark hardware is the cloud CPU named in the report, using headless Chromium; **no named physical mobile device was available**. The ≤33.3ms frame p95, ≤100ms input-to-presented-state, no art-attributable >50ms task, and ≤10% regression device targets remain **UNVERIFIED** regardless of these virtual-host numbers. The reported input measure ends at the next animation frame that observes the committed DOM action count; it is not physical touch latency or display scanout. Long tasks are recorded without invented art attribution. JS heap snapshots are not decoded-image/GPU accounting or a leak certification.

Responsive reveal differs from square presentation by 17.918% more logical rows for equal pixel height before clamp/padding. The report records actual clip extents, rather than assuming production camera fairness transfers to this view. No timing, leaderboard or ranked policy has been changed.
